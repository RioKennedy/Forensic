# windows.mutantscan.MutantScan 分析

## 1. Plugin 功能說明

`windows.mutantscan.MutantScan` 用來掃描記憶體中的 Mutant Object，也就是 Windows 中常見的 Mutex 類型同步物件。

惡意程式常會建立 Mutex / Mutant，用來避免自己重複執行，或用來標記感染狀態。

因此，在惡意程式分析中，Mutant 名稱有時可以作為辨識惡意程式家族或執行狀態的輔助證據。

---

## 2. 執行指令

```bash
.\vol.exe -f .\OtterCTF.vmem windows.mutantscan.MutantScan
```

---

## 3. 欄位說明

| 欄位       | 說明                     |
| -------- | ---------------------- |
| `Offset` | Mutant Object 在記憶體中的位置 |
| `Name`   | Mutant / Mutex 名稱      |

---

## 4. 執行結果摘要

本次 `MutantScan` 掃描到大量 Mutant Object，但結果中的 `Name` 欄位幾乎全部顯示為：

```text
N/A
```

這表示 Volatility 有掃描到 Mutant Object，但沒有解析出可讀取的 Mutant 名稱。

---

## 5. 結果分析

本次結果沒有發現明確可疑的 Mutant 名稱，例如：

```text
Rick
Morty
vmware
ransom
crypt
encrypt
locker
malware
```

因此，`MutantScan` 沒有提供可以直接連結到本案惡意程式的 Mutex / Mutant 證據。

需要注意的是，沒有 Mutant 名稱不代表沒有惡意行為，只代表此 Plugin 沒有取得可用的命名 Mutex 證據。

---

## 6. 與 Handles 的比較

雖然 `MutantScan` 沒有解析出可疑名稱，但前面的 `Handles` 分析中，PID 3820 與 PID 3720 都有出現多個 Mutant handle。

例如 PID 3820 `Rick And Morty` 出現多個 Mutant，而 PID 3720 `vmware-tray.ex` 也出現多個 Mutant。

但這些 Mutant 大多沒有可疑名稱，或屬於正常 Windows / Internet Explorer / Zone 相關同步物件，因此不能單獨判斷為惡意。

---

## 7. 鑑識判斷

本次 `MutantScan` 結果可作為輔助檢查，但不是本案的主要證據。

原因如下：

```text
1. 掃描到大量 Mutant Object
2. 多數名稱為 N/A
3. 沒有發現明確可疑 Mutex 名稱
4. 沒有看到與 Rick And Morty 或 vmware-tray.exe 直接相關的 Mutant 名稱
```

因此，不能用此結果直接證明惡意程式家族或感染標記。
